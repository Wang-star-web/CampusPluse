## 一、任务

打通并验收 **模拟器 → MQTT → FastAPI 内存状态 → WebSocket → 浏览器最小看板** 数据链路：
统一消息外壳（activity_id/object_type/observed_at/source_type/data，全部属于 `campus_open_day_01`）；
4 类模拟数据源（crowd 300/500/650/750/900、entrance 2/2/1/2、main_route normal/limited、support 8/10/12），
只输出原始业务状态；FastAPI 订阅 MQTT 保存内存最新状态并暴露 `GET /api/current`；WebSocket 实时推送；
本阶段不做态势计算/影响/run_id/SQLite。

## 二、关键决策与纠偏

1. **main.py 保留 Day1 全部演示路由**（用户拍板），阶段01 只做加法：/health、/api/current、/ws、MQTT 启停。
2. **模拟器改值用配置文件热读**（用户拍板）：每个发布周期（2s）重读 `simulators/sim_values.json`，
   改文件即生效、无需重启；非法值沿用上次有效值并告警。
3. **entrance 的 data 字段纠偏**：最初设计 `{"open":1}`，对照官方指南阶段02/03 示例改为
   `{"available":2,"total":2}`（`entrance_ratio = available / total`），阶段02 映射 `value_json` 零转换。
4. **object_type 统一为 main_route**：指南 topic 示例写 `state/route` 但注明"不是唯一写法"，
   任务要求与指南业务字段均为 `main_route`；schema 枚举、模拟器、topic 尾段、前端键名四者统一为 `main_route`。
5. **订阅策略**：通配订阅 `campuspulse/+/state/+`，按信封 `activity_id` 过滤——信封是权威维度，
   topic 只是传输路径；未知 object_type 由 pydantic 枚举拒绝。
6. **Mosquitto 复用系统已装实例**（项目内自带 `mosquitto/mosquitto.conf`：127.0.0.1:1883、匿名允许、
   persistence false）；模拟器 `retain=False`，保证重启不依赖残留。

## 三、AI 出错与纠正（开发过程中的真实问题）

1. **paho-mqtt 2.x API 踩坑**：`subscribe()` 返回的 `MQTTErrorCode` 没有 `is_failure` 属性
   （只有回调参数 `ReasonCode` 才有），按 1.x 习惯写导致订阅失败、后端收不到任何消息。
   实测 API 后改为 `err != MQTTErrorCode.MQTT_ERR_SUCCESS`。
2. **WebSocket 增量推送不工作**：`StateStore` 的 listener 机制已实现，但 `mqtt_bridge.start()`
   忘了注册 `store.add_listener(ws_hub.notify)`，MQTT 消息只进了内存、没进广播。
   WebSocket 客户端实测"快照有、增量无"暴露问题后补上注册/注销。
3. **模拟器 docstring 反斜杠**：`py simulators\crowd_sim.py` 中 `\c` 触发 SyntaxWarning，改为正斜杠。
4. **旧 uvicorn --reload 残留 worker**：杀掉监听 8000 的父进程后端口仍被占用，
   排查发现 reload 子进程（`spawn_main(parent_pid=58936)`）继承了监听 socket，需连子进程一起结束。
